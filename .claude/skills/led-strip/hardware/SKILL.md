# 硬件: WS2811/WS2812B 灯带

## 1. 电气 —— 先看这个再接线

| 项 | 值 | 出处 |
|---|---|---|
| 每颗全白电流 | **60 mA** | `firmware/esp32s3/src/led_limits.h` 注释 |
| 176 颗全亮 | 176 × 60mA ≈ **10.5 A** | 同上 —— 供电扛不住, 会把板子/USB 拉垮 |
| 352 颗全亮 | ≈ **21 A** | 同上 |
| **同时点亮上限** | **30 颗** (≈ 1.8 A) | `LED_MAX_LIT = 30`, 固件写死不可配 |
| 数据协议 | 24 bit/颗, 800 kHz, 1.25 µs/bit → **30 µs/颗** | `WS2811 800kHz` |
| 一帧 (176 颗) | ≈ **5.3 ms** | 实测 6.78 ms |
| 颜色顺序 | **GRB** (`WS2811_STRIP_GRB = 0x00081000`) | `scripts/bt_pi/pi/led_remote.py:43` |

**接线三条铁律**:

1. **独立 5V 供电** —— 灯带的电源**不要**取自树莓派的 5V pin (只能供 ~1A)。
   ESP32 侧同理: 用外部 5V 给灯带供电, 只把数据线和地接到板子。
2. **GND 必须共地** —— 灯带 GND 与树莓派/ESP32 的 GND 必须连在一起。
   不共地 = 数据线没有共同参考电平 = 全黑 / 乱闪 / 随机亮, 而且**看起来像软件 bug**。
3. **DIN 只接一处** —— 两条带串联时数据线从第一条 DIN 进、第一条 DOUT 出、第二条 DIN 进。

**电平提醒**: 项目实测 3.3V (树莓派 GPIO / ESP32 GPIO) 直连 WS2812B 可用
(`firmware/esp32s3/README.md`)。但 WS2812B 规格上 VIH ≈ 0.7 × VDD = 3.5 V ——
若出现**随机误码 / 无规律闪烁**且供电共地都正常, 先怀疑电平 (加电平转换或串 74AHCT),
不要一上来改代码。

## 2. 引脚

| 平台 | 引脚 | 备注 |
|---|---|---|
| 树莓派 (默认) | **GPIO 18** | PWM0_0。`led_remote.py` 的 `DEFAULT_PIN` |
| 树莓派 (备选) | GPIO 12 | 也是 PWM0_0, **不能和 18 同时用** |
| 树莓派 (备选) | GPIO 21 | PWM1_0 |
| ESP32-S3 | **GPIO 14** | 编译期固定 (`platformio.ini` 的 `LED_PIN`), 前端传的 pin 被忽略 |

**树莓派只有 12 / 18 / 21 能驱动 WS2812** —— `rpi_ws281x` 对其他引脚一律报
`Gpio N is illegal for LED channel 0`。白名单 `DEFAULT_ALLOWED_PINS = (12, 18, 21)`。

**pinmux (复用) 是独立的坑**: `rpi_ws281x` 只管 DMA, **完全不管引脚复用**。
GPIO18 被别的进程改成 input 时, `show()` 依然返回 ok, 但 DIN 线上没有波形 → 灯全黑。
- Pi4 (BCM2711): GPIO18 的 PWM 功能是 **alt5**
- Pi3 (BCM2837): GPIO18 的 PWM 功能是 **alt0**

查法 `pinctrl get 18`; 修法见 raspberry-pi 技能。

## 3. 键 → LED 索引映射

一条灯带 = **88 键 × 2 颗** = 176 颗。键序 A0(21) … C8(108), **0-based**:

```
key k (0..87)  →  chain [2k, 2k+1]
```

| 键 | k | chain |
|---|---|---|
| A0 (21) | 0 | `[0, 1]` |
| C4 (60) | 39 | `[78, 79]` |
| C8 (108) | 87 | `[174, 175]` |

- 实现: `src/led/dualStrip.ts` 的 `stripRange(note)`
- 索引 0 = **最低音 A0**, 与前端 `LedController` / 固件 USB 串口命令的索引一致。
- 每个音固定 **2 颗灯** → 所以「亮着的灯是奇数颗」几乎一定是出 bug 了
  (偶数颗成对才可能是正常状态)。

## 4. 双色带 (两条串联 = 352 颗)

- 主灯带 = chain `0..175`, 上灯带 = chain `176..351`。
- **上灯带是反着接的** (接缝在最右端), 所以它的局部序号方向跟物理从左到右相反。
  项目做法 = **补偿**: 让两条带的**物理位置对齐** (上带第 0 颗 = 物理最左)。

```
key k → 上灯带 chain [352 - (2k+1), 352 - 2k]
```

| 键 | 主灯带 | 上灯带 | 物理位置 |
|---|---|---|---|
| A0 | `[0,1]` | `[350,351]` | 最左 ✓ |
| C4 | `[78,79]` | `[272,273]` | 中间偏左 ✓ |
| C8 | `[174,175]` | `[176,177]` | 最右 (接缝) ✓ |

- 实现: `src/led/dualStrip.ts` 的 `upperRange(note)`
- **帧长永远按物理链发 (352)**。WS2812 是串联的: 服务端发出去的比特流如果比物理链短,
  后面的那条带收不到自己的数据, 移位寄存器被空闲高电平填满 → **整条带全白**
  (176 颗全白 ≈ 10 A!)。发得比物理链**长**是安全的。
  → `led_remote.py` 的 `DEFAULT_PHYSICAL_COUNT = 352`, `init` 来的 count 只当
  「逻辑可寻址长度」。

## 5. 亮度与配色

**亮度只在主机侧乘一次**:

- 前端 `LedController` 已经把 `brightness` 乘进 RGB。
- 树莓派 `rpi_ws281x` 是满亮度 (255), 固件 `LED_BRIGHTNESS` 也是 255 ——
  设备端**不要再乘**, 否则比树莓派暗一倍。
- 前端默认 `ledBrightness = 0.5`; 双色带上灯带另乘一个比例
  (`ledUpperBrightnessRatio`, 默认 0.7)。

**配色语义** (4 色调色板):

| 颜色 | 含义 |
|---|---|
| 红 | 右手白键 |
| 橙 | 右手黑键 |
| 蓝 | 左手白键 |
| 绿 | 左手黑键 |

上灯带的「下一个音」复用同一套配色 (左手色 / 右手色), 所以上下两条带是同一套语言。

**上灯带的亮度递减**: 第 i 个 (0-based) 亮度 = `0.65 ** i`
(`UPPER_LEVEL_FALLOFF`, `src/led/dualStrip.ts`), N ∈ 2..6 (`ledUpperNoteCount`, 默认 3)。
上限 6 的原因: 4N 颗上灯带 + 第一排的一组 ≤ 30 颗 (见根技能的硬约束 1)。
