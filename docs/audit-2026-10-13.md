## A. 真 bug(会导致用户场景失败)

### A1. `Accompaniment.ts:62-67` — 通道错配(影响所有右手伴奏)
```ts
sendNoteOn(n: SongNote) {
  ...
  const ch = n.hand === 'left' ? 0 : 1  // ← 罗兰默认只收 ch=0
  ...
  this.output.send([status, n.midiNote, 100])
}
```
**现象**:单手选「左手」→ 右手从罗兰发 → 罗兰不响(默认接收 ch=1 的型号才会响)。
**实测**:用户按键全部在 ch=0,罗兰本地默认也是 ch=0。
**修法**:
```ts
const ch = 0  // 罗兰默认 ch=0;多声部由罗兰面板切换
this.output.send([status, n.midiNote, n.velocity ?? 100])
```

### A2. `Accompaniment.ts:66` — 力度写死 100
```ts
this.output.send([status, n.midiNote, 100])
```
**现象**:丢了音符自带的 `n.velocity`(从 MIDI 解析来的 0-1)。
**修法**:`n.velocity ?? 100`

### A3. `Accompaniment.ts` — 缺 `panic()` 方法(异常路径不收尾)
**现象**:用户切歌 / 浏览器刷新 / WebMIDI 断开时,罗兰里挂住的音会一直响。
**修法**:加 `panic()`,在所有退出路径调用:
```ts
panic() {
  if (!this.output) return
  for (let ch = 0; ch < 16; ch++) {
    this.output.send([0xB0 | ch, 123, 0])  // All Notes Off
  }
}
```
并在 `use(null)`、`disconnect`、`pagehide` 事件里调用。

### A4. `Player.ts:69-79` — `pause()` 不清 `playingNotes`
```ts
pause() {
  ...
  for (const n of this.playingNotes) {
    this.synth.stopNote(n.midiNote)
    this.acc.stopAll([n])
  }
  // 没有 this.playingNotes.clear()
}
```
**现象**:连续 pause/play 几次后,旧 note 残留在 `playingNotes` 里,占用内存;且 `stopAll([n])` 每次都新建一个 1 元素数组。
**修法**:
```ts
pause() {
  ...
  for (const n of [...this.playingNotes]) {
    this.synth.stopNote(n.midiNote)
    this.acc.stopAll([n])
  }
  this.playingNotes.clear()
}
```

### A5. `Player.ts:144-173` — 调度 inactive 音符时,即使 acc 未启用也应该调用 synth 兜底(已有),但 active 检测有 bug
**重读**:代码逻辑看起来对(active → synth + lateNotes,inactive → MIDI 或 fallback synth)。
**已通过 mido 实测**:sample.mid 经此路径可被罗兰播放。✅
**无需改**。

## B. UX 设计问题(用户踩过的坑)

### B1. `store.ts:53` — 默认 `hand: 'both'` 是用户「没声音」的主因
**现象**:默认双手模式下,**没有任何 note 走 MIDI Out**(都在浏览器 synth 里)。用户即使配好 MIDI Out 也听不到罗兰响。
**修法**:
- **方案 A**(最小):默认改 `hand: 'right'`(左手走 MIDI Out)
- **方案 B**(更好):保持 `'both'`,但当 MIDI Out 选中时,自动把**左手**走 MIDI、**右手**走 synth(最常见的练习场景)
- **方案 C**(最清晰):UI 上明确显示「当前哪些手会从罗兰发出」,以及「双手模式 = MIDI Out 关闭」提示

**建议**:同时做 A + C。先把默认改成 `'right'`,UI 在 hand='both' + MIDI Out 选中时显示警告条。

### B2. `DeviceSelector.tsx` — 不响应 `access.onstatechange` 刷新
**现象**:用户拔了罗兰重插,设备列表不更新,需要重新点「申请权限」。
**修法**:在 `requestPermission()` 里挂 `access.onstatechange`,触发重新 `setInputs` / `setOutputs`。

### B3. `DeviceSelector.tsx` — 没给「为什么没声音」诊断
**现象**:用户看到 MIDI Out 选好,但没声音 — 不知道是 hand='both' 还是通道问题。
**修法**:当选中 MIDI Out 且 `hand === 'both'` 时,显示提示:
> ⚠️ 双手模式下 MIDI Out 不发任何音符,切「左手」或「右手」即可
