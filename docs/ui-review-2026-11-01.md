## 0. TL;DR

| 级别 | 数量 | 一句话 |
|---|---|---|
| **A 系统级** | 5 | 滑块轨道与面板同色导致**隐形**、分段控件**右侧留空**、checkbox 未定制、字号体系缺失、中文标题上用 `uppercase/tracking-wider` |
| **B 进阶设置抽屉** | 8 | 无视觉分组、标题正文同权重、transport 大按钮喧宾夺主、`Row` 布局 bug（滑块与数值上下分离）、说明文字无容器、LED 段落与浮窗重复 |

| **E/F 顶栏·底栏** | 3 | 进度条几乎不可见、播放按钮权重过大、曲名区偏离中线 |
| **G 正面基准** | 1 | `StatsPopup` 是全 app 视觉最好的面板，应该作为其它面板的参照 |

**核心结论**：这个 app 的**信息架构是清楚的**（统计弹窗、登录弹窗做得不错），但**设置类界面没有设计系统**——所有控件都是各写各的 Tailwind class，没有共享组件，于是出现了「同一份设置在两个页面用两种布局」「同一个抽屉里 Row 的两种写法」「分段控件有的填满有的留空」这类不一致。

**最该先修的三件事**（改动小、收益最大）：
1. 滑块轨道颜色（`index.css` 改一行）—— 现在**用户根本看不见滑块的量程和当前位置**
2. 分段控件不填满（按钮加 `flex-1`）—— 现在每个分段控件右侧都是一块空白
3. 练习条高度统一 —— 现在一行 6 个控件**基线全是歪的**

## 2. 系统级问题（A 类）—— 影响每一个页面

### A1 【严重】滑块轨道与面板**同色** → 轨道完全隐形

**位置**：`src/index.css:87`

```css
input[type="range"] {
  height: 4px;
  background: #1a1c23;     /* ← 等于 tailwind 的 panel 色 */
  border-radius: 2px;
}
```

`tailwind.config.js` 里 `panel: '#1a1c23'`。**滑块轨道色 == 面板底色**。

**DOM 实测**：

| 滑块 | 轨道色 | 所在容器底色 | 同色？ |
|---|---|---|---|
| 练习条·音量 | `rgb(26,28,35)` | `rgba(15,16,20,0.6)` | 否（勉强可见，对比极低） |
| 抽屉·手动补偿 | `rgb(26,28,35)` | `rgb(26,28,35)` | **是 → 完全隐形** |
| 抽屉·上灯带亮度 | `rgb(26,28,35)` | `rgb(26,28,35)` | **是 → 完全隐形** |

**截图实证**：抽屉里「手动补偿」那行只剩**一个孤零零的蓝色圆点**浮在面板上，看不出轨道、看不出量程、看不出当前值在哪个位置（0ms 在最左，但因为轨道隐形，用户根本不知道它是 0~500 的范围）。「亮度 50%」同理。

**修法**（改一行 + 加一个 token）：

```js
// tailwind.config.js
colors: {
  panel: '#1a1c23',
  track: '#3a3c45',        // 新增: 滑块轨道 (在 panel 和 bg 上都可见)
}
```

```css
input[type="range"] {
  height: 4px;
  background: #3a3c45;     /* 原来是 #1a1c23 */
}
```

再进一步建议给滑块做**已填充段**（`<div>` 覆盖左侧百分比），跟 `Transport` 进度条的做法统一。

### A2 【严重】分段控件不填满容器 → 右侧一大块空白

**实测**（抽屉里 4 个 + 练习条 1 个；源码里 `src/ui/` 共 **9 处**分段控件：SettingsDrawer 5 / LedDock 3 / HandSelector 1）：

| 控件 | 容器宽 | 子项总宽 | **右侧空白** |
|---|---|---|---|
| 自动(声部聚类) \| 按音高切分 | 319px | 184px | **135px** |
| 不标 \| 只标C \| 全标 | 227px | 141px | **86px** |
| 树莓派 \| ESP32 | 227px | 109px | **118px** |
| 单灯带 \| 双色带 | 227px | 113px | **114px** |

**根因**：按钮是内容宽度（`px-2.5 py-1.5`），容器 `flex` 但 `justify-content` 默认 `flex-start` → 边框画满整个宽度，**按钮只占左边一段，右边是一块空的深色框**。

**截图实证**：抽屉里「标号」控件是一个带边框的长条，右边 1/3 是空白；LED 浮窗里「树莓派 | ESP32」右边更是有**一大半是空的**——用户会以为这是个可以点的空白区域。

**修法**：按钮加 `flex-1`（等分宽度），或容器改 `w-fit`（贴合内容）。**推荐 `flex-1`**——等宽的分段控件在 2~4 个选项时更整齐：

```jsx
<div className="flex rounded-lg overflow-hidden border border-border bg-bg">
  {options.map((o, i) => (
    <button className={`flex-1 px-2.5 py-1.5 ... ${i > 0 ? 'border-l border-border' : ''}`}>
```

> 练习条里的手别控件是唯一填满的（因为它的容器宽度正好由内容撑开），所以现在看起来"正常"——这掩盖了同一个组件在别处都留空的事实。

### A3 【一般】checkbox 是未定制的原生控件，深色底上很刺眼

`src/index.css:104` 只设了尺寸和圆角：

```css
input[type="checkbox"] { width: 16px; height: 16px; border-radius: 4px; cursor: pointer; }
```

配合 `accent-accent`（`accent-color: rgb(96,165,250)`）——**只影响选中态**。未选中时是系统默认的白色/浅灰方块，在 `#1a1c23` 的面板上非常扎眼。

**更糟的是两个 checkbox 并排时观感完全不同**（练习条实测）：

| 控件 | 状态 | 渲染结果 |
|---|---|---|
| Wait | `disabled: true`（playback 模式下无意义） | 深灰方块，几乎看不见 |
| 倒计时 | enabled | **纯白方块**，非常刺眼 |

一行里两个同样语义的开关，一个灰得消失一个白得刺眼，用户会以为 Wait 是禁用状态而倒计时是"高亮"。

**修法**：用 `appearance-none` 完全定制，深底 + 边框 + 选中打勾：

```jsx
<input type="checkbox" className="peer appearance-none size-4 rounded border border-border bg-bg
  checked:bg-accent checked:border-accent
  disabled:opacity-40
  after:content-[''] after:absolute after:hidden ..." />
```

（带勾号用 `background-image` 的 SVG data-uri 最省事。）

### A4 【一般】字号体系缺失：满屏 `text-[10px]` / `text-xs`

现状统计：`text-[10px]` 在 `src/ui/` 里出现 **17 次**（LedDock 9 / SettingsDrawer 4 / StatusBar 2 / TopBar 1 / Library 1），`text-xs`（12px）更多。另有 **13 处** `text-muted/80` / `text-muted/70` 这类透明度叠加写法。

- `text-[10px]` 的中文在 1x 屏上**基本不可读**（约等于 7.5pt）
- 辅助文字普遍用 `text-muted/80` / `text-muted/70` —— `muted` 是 `#9ca3af`，乘 0.7/0.8 后在 `#1a1c23` 上对比度掉到 **4:1 以下**，低于 WCAG AA 对小字的要求

**修法**：定三档，且**不再出现 10px**：

| 用途 | 规格 | Tailwind |
|---|---|---|
| Section 标题 | 13px / 600 / `text-text` | `text-[13px] font-semibold text-text` |
| 正文 / 标签 | 13px / `text-muted` | `text-[13px] text-muted` |
| 辅助说明 | 12px / `text-subtle`（新增色） | `text-xs text-subtle` |

`text-subtle` 建议 `#8b8f9a`（比 `muted` 稍暗但仍 ≥ 4.5:1），**不要用透明度叠加**——`/70` 这种写法让对比度不可控。

### A5 【一般】中文标题上用 `uppercase tracking-wider` 是负作用

**位置**：`src/ui/SettingsDrawer.tsx` 的 `Section` 组件

```jsx
<div className="text-xs font-semibold text-muted uppercase tracking-wider">{title}</div>
```

`uppercase` 对中文**完全无效**（中文没有大小写），`tracking-wider`（0.05em 字距）作用在汉字上**只会让字散开、显得松垮**。这个写法明显是从英文 UI 抄来的。

而且标题用的是 `text-xs`（12px）+ `text-muted`，**跟正文完全同字号同颜色** → 层级为零。整个抽屉看起来就是一片均匀的灰色小字。

**修法**：

```jsx
<div className="text-[13px] font-semibold text-text">{title}</div>
```

去掉 `uppercase tracking-wider`，把标题字号抬到 13px、颜色提到 `text-text`（`#e5e7eb`），与正文的 `text-muted`（`#9ca3af`）拉开层级。

## 3. 进阶设置抽屉（`SettingsDrawer.tsx`）

### B1 【严重】`Row` 组件的布局 bug：内容垂直堆叠

**位置**：`SettingsDrawer.tsx` 的 `Row` 组件

```jsx
function Row({ label, children }) {
  return (
    <label className="flex items-center gap-3 w-full">
      <span className="text-xs text-muted w-20 shrink-0">{label}</span>
      <div className="flex-1">{children}</div>   {/* ← 不是 flex 容器! */}
    </label>
  )
}
```

内容容器是 **block**，不是 flex → 传入的多个子元素**垂直堆叠**而不是并排。

**同一个文件里两种写法并存**：

| Row | 写法 | 结果 |
|---|---|---|
| 手动补偿 | `<input>` + `<span>` 直接传 | ❌ **堆叠**——滑块在上，「0 ms」掉到下一行 |
| 亮度 | 外面自己套了 `<div className="flex items-center gap-2 w-full">` | ✅ 并排 |
| 标号 | 同上，自己套了 flex div | ✅ 并排 |
| 灯带模式 | 分段控件 + `<p>` 直接传 | ⚠️ 堆叠（这个恰好是对的，说明文字确实该换行） |

**截图实证**：抽屉里「手动补偿」那一行，蓝色滑块圆点浮在左边，**「0 ms」掉到了它的正下方**，而且因为 label 是 `items-center` 垂直居中于整个堆叠块，「手动补偿」四个字跟滑块**没有对齐**。

**修法**：把内容容器改成 flex，并让「有说明文字」的行显式声明换行：

```jsx
function Row({ label, children, hint }) {
  return (
    <div className="flex items-start gap-3 w-full">
      <span className="text-[13px] text-muted w-[88px] shrink-0 pt-1">{label}</span>
      <div className="flex-1 flex items-center gap-2 min-w-0">{children}</div>
      {hint && <p className="text-xs text-subtle leading-relaxed">{hint}</p>}
    </div>
  )
}
```

即：**说明文字从「Row 的子元素」改成「Row 的 hint 属性」**，这样结构就统一了，也不会再出现"有的堆叠有的并排"。

### B2 【严重】抽屉顶部两个 transport 大按钮喧宾夺主

```jsx
<Section title="播放">
  <div className="flex items-center gap-2 mb-3">
    <PrimaryBtn onClick={onRestart}>↻ 重置开头</PrimaryBtn>
    <PrimaryBtn onClick={isPlaying ? onPause : onPlay} tone={...}>{isPlaying ? '⏸ 暂停' : '▶ 播放'}</PrimaryBtn>
  </div>
</Section>
```

两个 44px 高的**实心蓝按钮**（`bg-accent text-bg`），是整个抽屉里**视觉权重最高的元素**，而它们：

1. **在底栏已经有**（重置 / 播放暂停）——重复
2. 语义完全不同却**权重完全相同**（"重置开头"和"播放"都是主按钮）
3. 放在一个叫「**进阶设置**」的抽屉的最顶部，与"进阶"的定位矛盾

**修法**：

- **直接删掉**「播放」这一节——底栏有，位置也更对
- 「重置开头」同理（快捷键 R，底栏也有）
- 如果要保留（比如用户全屏时底栏不可见），改成**次级按钮**（描边）并移到底部

### B3 【严重】没有视觉分组：整面墙的灰色小字

抽屉的内容是 `flex flex-col gap-5`，每个 `Section` 是 `flex flex-col gap-3`。**Section 之间只有 20px 间距，没有任何分隔**。

在 480px 高的可视区里，用户看到的是：

```
播放
[蓝色大按钮][蓝色大按钮]
节拍器声音
跟随谱面 BPM 发声 (重音按拍号首拍)。
判定延迟
检测到的输出延迟: 0 ms (蓝牙耳机常在 100~200ms)
按检测值自动补偿
手动补偿 [滑块]
默认不补偿 —— 跟弹时被判定的那只手本身不发声, 用户是照着画面弹的, ...
手别判定
...
```

**每一行看起来一样重要**。用户没法快速扫出"哪几项需要改"。

**修法**（三选一，从轻到重）：

1. **加分隔线**（最省）：`Section` 之间加 `border-t border-border/60 pt-4`（第一个不加）
2. **给 Section 加卡片底**：`rounded-lg bg-bg/40 p-3.5` —— 面板浮起来，层级立刻清晰
3. **改成可折叠分组**（进阶设置本就该折叠）：默认只展开「常用」，其余折叠

推荐 **1 + 3 组合**：Section 之间加细分隔线，同时把「调试/元数据」这类真正低频的折叠起来（当前只有一个"展开更多"折叠的是调试信息，LED/判定延迟这些也是低频的）。

### B4 【一般】标题与正文的层级为零

已在 A5 提到，这里补充**具体表现**：

| 元素 | 当前规格 |
|---|---|
| Section 标题（"判定延迟"） | `text-xs` (12px) / `font-semibold` / `text-muted` |
| 正文（"检测到的输出延迟…"） | `text-xs` (12px) / `text-muted` |
| 辅助说明 | `text-[10px]` / `text-muted/80` |

标题和正文**只差一个 `font-semibold`**，在深色底上几乎看不出差别。

**修法**见 A5：标题 13px + `text-text` + `font-semibold`，正文 13px + `text-muted`，辅助 12px + `text-subtle`。

### B5 【一般】checkbox 的呈现方式在同一面板里不统一

- 「节拍器声音」：checkbox **在 Section 标题里**（标题本身就是 checkbox）
- 「按检测值自动补偿」：checkbox **在正文里**
- 「LED 灯带跟随」：checkbox **在标题里**，还带一个状态徽章
- 「中央 C 校准」「跟随源」「提前按」：checkbox **在 Row 的内容里**
  （「提前按」这个开关 2026-11-05 随「抢先」二选一被删掉了 —— 见 spec §R23）

四种不同的呈现方式。

**修法**：统一成「**标题行右侧放开关**」：

```jsx
<Section title="节拍器声音" action={<Switch checked={metronome} onChange={...} />}>
```

`Section` 加一个可选的 `action` 槽位，所有开关型设置都用它。这样标题是标题、控件是控件，扫读性最好。

### B6 【一般】长说明文字直接铺在正文流里

例：

> 默认不补偿 —— 跟弹时被判定的那只手本身不发声, 用户是照着画面弹的, 画面没有延迟。只有「跟着伴奏声音弹」的用户才需要开补偿。

3 行 `text-xs text-muted` 直接铺开，没有任何视觉容器，**跟上面的控件混在一起**，读者分不清这是"说明"还是"又一个设置项"。

**修法**：辅助说明统一用「次级容器 + 左侧竖线」的样式：

```jsx
<p className="text-xs text-subtle leading-relaxed border-l-2 border-border pl-2.5">
  默认不补偿 —— ...
</p>
```

竖线 + 更暗的文字，一眼区分"说明"和"控件"。

### B7 【一般】标签列固定 80px，7 个汉字的标签会换行

`Row` 的标签列是 `w-20`（= 80px）。实测当前所有标签（最长「中央 C 校准」≈ 76px）**都在临界值内，没有溢出**。

但有两个**条件渲染**的标签会超：
- 「上灯带显示几个」= 7 个汉字 ≈ 84px > 80px → **换行**
- 「上灯带亮度」= 6 个 ≈ 72px（勉强）

**修法**：标签列放宽到 `w-[88px]`，或把长标签改成「上灯带·亮度」「上灯带·音数」。

### B8 【轻微】「调试 / 元数据」用 `<pre>` 直接吐 JSON

```jsx
<pre className="text-xs text-muted leading-relaxed whitespace-pre-wrap break-words">
  {JSON.stringify({...}, null, 2)}
</pre>
```

能跑，但排版是 JSON 原文（带缩进和引号），不是 UI。**改成键值对网格**会好看得多，也更容易扫读。

## 4. LED 灯带浮窗（`LedDock.tsx`）

### C1 【严重】与进阶设置抽屉的 LED 段落**几乎完全重复**

| 设置项 | LED 浮窗 | 进阶设置抽屉 |
|---|---|---|
| 开关 | ✅ 灯带跟随 | ✅ LED 灯带跟随 |
| 灯带后端 | ✅ | ✅ |
| 灯带模式（单/双色） | ✅ | ✅ |
| 亮度 | ✅ | ✅ |
| 上灯带亮度 | ✅ | ✅ |
| 上灯带显示几个 | ✅ | ✅ |
| 中央 C 校准 | ✅ | ✅ |
| 跟随源 | ✅ | ✅ |
| 4 色调色板 | ✅ | ✅ |

**9 项里有 8 项重复**。而且两处的**布局语言还不同**：

- 抽屉：有 `w-20` 标签列，`Row` 对齐
- 浮窗：**没有标签列**，标签直接顶在上面

于是同一个「亮度」在两个地方长得不一样（一个「亮度 50%」左对齐带滑块，一个滑块孤零零居中）。

这不只是"不美观"——它是一个**真实的可用性问题**：用户改了浮窗里的亮度，打开抽屉会以为"怎么又变回去了"。

**修法**（推荐方案 A）：

- **方案 A（推荐）**：抽一个 `<LedSettings />` 组件，两处**复用同一份**。浮窗放高频项（开关/亮度/跟随源/后端），抽屉放低频项（双色带细节/校准/调色板），但**渲染用同一个组件**，保证样式永远一致。
- 方案 B：浮窗只留「开关 + 亮度 + 状态」，其余全部指向抽屉（浮窗里给一个「更多设置 →」按钮跳到抽屉）
- 方案 C：删掉浮窗，只保留抽屉（但浮窗是顶栏 💡 的直接落点，删了会多一次点击）

### C2 【一般】浮窗内同样有 A2（分段控件留空）的问题

实测「树莓派 | ESP32」容器 227px、子项仅 109px → **118px 空白**，占容器一半以上。截图里非常明显。

## 5. 主区练习条（PracticeBar）

### D1 【严重】6 个控件高度各异，基线完全没对齐

**DOM 实测**（练习条直接子元素的实际高度）：

```
手别分段控件      34px
Wait              20px   ← 差 14px
容差              30px
倒计时            20px   ← 差 14px
音量              16px   ← 差 18px（！）
倍速 select       28px
分隔线            34px
```

配合 `items-center`（`App.tsx` 里是 `flex items-center`），结果是**一行控件上下跳动**：音量滑块最矮、Wait/倒计时次矮、分段控件最高。用户视觉上找不到一条统一的基线。

**根因**：每个组件各自决定自己的高度（`py-1`、`py-1.5`、`py-2`、原生 checkbox 16px、原生 range 4px）。

**修法**：统一控件高度。

```jsx
// 统一 h-7 (28px) 的控件高度
const CONTROL_H = 'h-7'
```

- 分段控件按钮：`h-7` 替代 `py-1.5`
- Wait/倒计时：给 checkbox 包一个 `h-7 flex items-center`
- 音量滑块：包一个 `h-7 flex items-center`
- 容差数字框：`h-7`
- 倍速 select：`h-7`
- 练习条本身：`items-stretch` 或保持 `items-center` 但控件等高后自然对齐

### D2 【一般】手别标签是一个孤零零的「手」字

**位置**：`src/ui/HandSelector.tsx`

```jsx
<span className="text-xs text-muted shrink-0">手</span>
```

「手」单独一个字，语义不完整（手什么？手别？演奏方式？），在整行里像一个被截断的词。

**修法**：改成「手别」；或者更明确「演奏」；或者**直接去掉标签**——分段控件里已经有 🎹/🤲/👉/👈 图标和"钢琴播放/双手/右手/左手"文字，本身已经自解释，标签是冗余的。

### D3 【一般】警告文字夹在控件流中间

```jsx
{hand === 'playback' && !midiOutputId && (
  <span className="text-xs text-miss">⚠ 需连接电钢</span>
)}
```

它出现在分段控件和分隔线之间，**打断了控件流的节奏**，而且一行里同时有控件、控件、红色告警、控件、控件……

**修法**：把状态提示做成**统一的 status slot**——比如放到底栏（StatusBar 已经有"电钢/ MIDI / LED"三个连接框，加一个"需连接电钢"很自然），或做成手别控件的 tooltip / 小角标。

### D4 【轻微】容差数字框与其它控件不统一

`ToleranceInput` 的 input 是 `w-16 px-1.5 py-1 ... rounded border`，而其它控件没有可见边框（音量是无边框滑块）。一行里一个有边框圆角矩形、旁边是无边框控件，观感不统一。

**修法**：给所有输入类控件统一 `h-7 px-2 rounded border border-border bg-raised`（新增 `raised` 色）。

### D5 【轻微】音量没有单位

`VolumeSlider` 只显示 `60`，没有 `%`。而抽屉里的亮度显示 `50%`。同一类信息两种写法。

**修法**：统一加 `%`。

## 6. 顶栏（`TopBar.tsx`）与底栏（`Transport.tsx`）

### E1 【一般】曲名区偏离视觉中线

```jsx
<div className="flex-1 min-w-0 max-w-[55%] flex items-center justify-center overflow-hidden">
```

曲名在「logo 与右侧按钮排之间」的剩余空间里居中，而不是在**整个顶栏**居中。因为左侧 logo 比右侧图标排宽，**曲名整体偏右**。

**修法**：把曲名区改成绝对定位居中，或用 `flex-1` 对称分配（左右各放一个 `flex-1` 的空占位）。

### E2 【轻微】图标排太挤

`gap-0.5`（2px）+ 每个 `size-9`（36px）→ 视觉上 6 个图标连成一片，且 💡 图标上还挂了一个状态小圆点（`absolute -top-0.5 -right-0.5 size-1.5`），**紧挨着右边的 🎹 图标**，容易看成是它的角标。

**修法**：`gap-1`；状态点改成 `ring-2 ring-panel`（已经有）再往外挪一点，或改用图标本身变色。

### F1 【严重】进度条几乎不可见

```jsx
<div className="flex-1 relative h-2.5 bg-bg rounded-full border border-border overflow-hidden ...">
```

`bg-bg` = `#0f1014`，外层是 `bg-panel/40`（≈ `#141519`）→ **底色几乎一致**，只有 1px 的 `border-border` 撑着。截图里底栏的进度条就是一条若有若无的细线。

同一个根因同 A1：**滑块/进度条用了跟容器同色的 token**。

**修法**：轨道用 `bg-raised`（新增 `#22252d`），已播放段 `bg-accent/70` 保持。

### F2 【一般】播放按钮权重远大于其它元素

`size-11`（44px）实心蓝圆 + `hover:scale-105` + `hover:shadow-lg hover:shadow-accent/30`，而旁边的重置按钮是 `size-9` 灰色无背景。

播放/暂停是主要操作没错，但**44px 实心蓝圆 + 发光阴影**在一条 44px 高的底栏里过于抢眼（截图里它比整个 Transport 区域都醒目）。

**修法**：`size-10`、去掉 `shadow-lg`、保留 `hover:scale-105`；或者统一成 `size-9` 的图标按钮，用 accent 色做图标而非实心块。

## 12. 第二轮施工（2026-11-01）—— 图标现代化 + 「灯带后端/模式」选项卡片

> 触发: 用户反馈「设置里的**灯带后端**和**灯带模式**不要用现在这种 看不到另一个选项」，
> 以及「所有 ico 图标等弄成现代化审美的」。

### 12.1 用户反馈的根因

上一轮 (§11.1) 把「灯带后端 / 灯带模式」从并排按钮换成了 **`<ArrowSwitch>` 左右切换**，
理由是「两个并排按钮占满整行很笨重」。但这个控件**屏幕上永远只有当前值**：

```
┌─────────┬──────────────┬─────────┐
│    ‹    │    树莓派     │    ›    │
└─────────┴──────────────┴─────────┘
```

用户根本不知道「还能选什么」—— 得先猜、再点箭头试。**这轮换回「所有选项同时可见」**，
但不是上一轮那种笨重的并排文字按钮，而是**选项卡片**。

### 12.2 新控件：`<OptionPicker>`（`src/ui/controls.tsx`）

## 16. 谱子编辑器（MIDI / MXL）（2026-11-02）

**诉求**：开发一个 MIDI / MXL 编辑器，能快速简单改谱子（主要改音和长度）；
右键色块能快速定位过去；乐谱文件那里能右键打开和更改；要有简易播放能力。

### 16.1 视图

`src/ui/ScoreEditor.tsx` —— 全屏浮层，钢琴卷帘（piano roll）：

- **X = 时间**（可缩放 20~600 px/s），**Y = 音高**（每半音一行），左侧一条**琴键条**
- 音符按手别着色（右手蓝 / 左手橙），块里直接写**唯一编码**
- 顶部标尺画小节线 + 小节号，选中的音描黄边
- 几何换算 / 命中测试抽到 `src/editor/roll.ts`（纯逻辑，可单测）

### 16.2 编辑

| 操作 | 怎么做 |
|---|---|
| 改音高 + 时间 | 拖音符块（纵向 = 半音，横向 = 时间） |
| 改时值 | 拖音符块**右边缘** |
| 微调 | `↑`/`↓` = ±1 半音（`Shift` = 八度）；`←`/`→` = 挪 1/4 拍（`Shift` = 1 拍） |
| 删除 | `Delete` / `Backspace`，或属性面板的垃圾桶 |
| 添加 | 「添加音符」按钮（接在选中音后面） |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z`（工具栏也有按钮） |
| 选中 | 点音符；点左侧琴键条 = 试听那个音高 |

**删除用「墓碑」而不是 splice**：编辑过程中编号不漂移 —— 用户对号入座需要稳定编号。
真正剔除发生在「应用到当前曲目」那一刻。

### 16.3 三个出口

| 出口 | 精度 | 说明 |
|---|---|---|
| **应用到当前曲目** | 无损 | 就地改 `song.notes`（按时间排序，Player 的 Scheduler 要求升序），并更新 `song.duration` |
| **导出 .mid** | 无损 | `src/editor/exportMidi.ts`：自己按 tempo map 算 tick，直接喂 `addNote({ticks, durationTicks})` —— 不碰 `header.secondsToTicks`（那要依赖已排好的 tempo 事件） |
| **导出 .mxl** | 音高/时间精确 | `src/editor/exportMusicXml.ts`：左右手各一个 `<part>`，`<forward>` 填空隙，跨小节的音按小节线切开打 `<tie>`；`.mxl` = ZIP（`mimetype` 第一个且不压缩，OPC 规范） |

### 16.4 踩过的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| `@tonejs/midi` 的 `header.setTempo(bpm)` 只接一个参数 | 传两个 → bpm=0 → `BinarySearch.search` 死循环，**页面卡死** | 改用 `midi.header.tempos = [...]` + `midi.header.update()` |
| MIDI meta 是 **Latin-1** 不是 UTF-8 | 中文标题 `测试曲` → `KÕò` | `latin1Safe()` 只留 ASCII；真曲名放**下载文件名**（那儿是 UTF-8） |
| `<forward>` 的 duration 是**属性** | 本项目的 `parseXml` 之前只认子元素 → 标准写法的空隙整个丢掉，后面所有音的时间轴集体前移 | `forwardDuration()` 属性优先、子元素兜底；两种都认 |
| 小节末尾没补 `<forward>` | 小节内容长度 ≠ 小节线长度，MuseScore 会显示小节不完整；解析器按绝对 tick 累加 → 后面小节整体前移 | 每小节末尾补一个 `<forward>` 填满 |
| `parseXml` **不读** `<duration>` | 用「同 part 下一个音的时间 − 自己的时间」估时值 → MXL 往返时值会偏 | 不动解析器的时长语义；**无损路径是「应用到当前曲目」和「导出 .mid」**，导出的 .mxl 是给 MuseScore 这类外部软件用的（那边读 `<duration>`，时值正确） |

### 16.5 简易播放

用项目自己的 `Synthesizer`：

- 顶栏「播放 / 停止」「从这里」（从选中音开始播）

## 17. 第三轮收尾（2026-11-02）—— 琴键条 bug + 乐库行压扁

### 17.1 谱子编辑器的琴键条全是白的（真 bug）

左侧琴键条渲染出来是一整条白色，黑键一个都没有。**根因在白键跨行的算法算反了**：

```ts
// 错: 拿「下方」的白键当边界
const nextWhite = nextWhitePitch(p)          // 返回 p 下面最近的白键
ctx.fillRect(0, y, gridX, Math.max(v.rowH, (p - nextWhite) * v.rowH))
```

以 D (62) 为例：`nextWhitePitch(62)` 返回 C (60)，高度 = 2 行，矩形从 `y(62)` 往下画 2 行 ——
正好盖住 **C# (61) 黑键那一行**。而 D 在音高顺序里比 C# 大，所以是**后画**，把黑键整个刷掉了。
每一个黑键都被它上方那个白键盖住 → 整条琴键变成一片白。

**修法**：白键的高度边界应该是**上方**那个白键（C 要盖住 C# 那半格，E 只占一格）：

```ts
// 对: 白键从自己一直连到上方那个白键
const span = whiteKeySpan(p)                  // { topPitch: 上方白键-1, rows: 跨的行数 }
const top = pitchToY(v, span.topPitch)
ctx.fillRect(0, top, gridX, span.rows * v.rowH)
```

## 18. LED 灯带：配色方案 C / D + 预告行亮度阶梯（2026-11-02）

### 18.1 为什么换掉「橙」

用户实测反馈：**红和橙在快速演奏时区分度不够** —— 两者同属暖色连续段，色相差只有 20° 左右，
明度差又不够大；而蓝和亮蓝虽然同色相，冷色对明度差更敏感，反而更好分。

结论：右手黑键从「橙」改成**浅品红 / 玫瑰粉**（仍属红色系，但向品红偏一点，同时把明度拉高），
左手黑键保持亮蓝 / 微偏冰青；第二排整体做「轻微色彩漂移 + 降饱和」，
形成「第一排纯、第二排柔」的层次。亮度变化只动 HSV 的 **V**，不动 HSL 的 **L**，避免色相漂移。

### 18.2 两套方案（`src/led/schemes.ts`）

| 方案 | 当前行 (主灯带) | 预告行 (上灯带) | 呼吸幅度 | 定位 |
|---|---|---|---|---|
| **C（默认）** | 左白 `#2F6BFF` · 左黑 `#7FE3FF` · 右白 `#D7263D` · 右黑 `#FF9ECF` | `#4D7FC4` · `#A9D4E8` · `#C24A6A` · `#F2A7C2` | 0.06 | 耐看 —— 慢速 / 练习最舒服 |
| **D（快速）** | `#1F5FFF` · `#73E6FF` · `#D81E3F` · `#FF8AD8` | `#3F78C8` · `#9FD8F0` · `#B93A63` · `#F29AD0` | 0.08 | 右手黑键更偏品红，分离度最高 |

「自动」= 按曲速挑：平均 BPM ≥ 120 用 D，否则用 C。**自动只影响下发到灯带的颜色**，
不动用户手动调过的色。

「自定义」= 用户手动调过色之后的状态（选 C / D 可恢复预设）。

### 18.3 灯带从 4 色变 8 色

| 层 | 用途 | 配色 |
|---|---|---|
| 当前行（主灯带） | **现在**该弹的音 | 高饱和纯色 |
| 预告行（上灯带） | 左右手**接下来**的音 | 降饱和 + 轻微色彩漂移 |

`LedController` 新增 `setUpcomingColors()`；`applyUpper()` 改用预告行配色，主灯带仍是当前行配色。

### 18.4 预告行亮度：只设最高 / 最低，中间按等比数列

之前是写死的 `UPPER_LEVEL_FALLOFF = 0.65`（每往后一个 × 0.65）。现在改成用户设两个百分比，
中间的按**等比数列**插值：

```
最亮 88%  ──┐
             ├─ 等比 r = min/max
最暗 46%  ──┘

3 个音 → 88% → 64% → 46%     (中间那个 = √(88×46) = 64%)
5 个音 → 88% → 74% → 62% → 52% → 46%
1 个音 → 88%                 (那就是在最近的音, 取最亮)
```

纯函数 `ledLevelLadder(max, min, count)`（`src/led/schemes.ts`）→ App 每 50ms 生成 hint 时用。

### 18.5 档位加上「1」

`UPPER_MIN_NOTES` 从 2 改成 1 —— 「上灯带显示几个」现在是 **1 / 2 / 3 / 4 / 5 / 6**。

### 18.6 当前音「呼吸」

`LedController.setPulse(amp)` + `tickPulse(dtMs)`：亮度按 `1 + amp × sin(2π·phase)` 起伏，
周期 1.4s，**只动 V 不动色相**。App 每 50ms 走一帧，没亮着灯时零流量。

## 19. LED 方案 C 配色返工（2026-11-02）

### 19.1 反馈

实机试过 §18 的方案 C 后，用户反馈：**右手黑键的浅粉（`#FF9ECF`）和偏粉的绯红（`#D7263D`）太亮、扎眼**，
整条灯带看着不舒服。诉求：

- 右手用**红 / 深红**，黑键跟白键用**同一个色**（不再靠颜色区分黑白键）
- 左手用**正蓝**（白键）+ **品蓝**（黑键）
- 只改方案 C，方案 D 保持不变

### 19.2 方案 C 新配色

| 层 | 左白键 | 左黑键 | 右白键 | 右黑键 |
|---|---|---|---|---|
| **当前行（主灯带）** | `#1E1EFF` 正蓝 | `#4169E1` 品蓝 | `#C8102E` 深红 | `#C8102E` 深红 |
| **预告行（上灯带）** | `#4D7FC4` | `#7C86C8` | `#96374A` | `#96374A` |

理由：

- 右手两键同色 → 同一只手不靠颜色区分，避开亮粉；深红 `#C8102E`（HSL 350° / 85% / 42%）
  相对亮度只有 0.22，不刺眼，色相落在红区 340~360°，**不是粉**（粉 = 品红区间 300~340°）。
- 左手白键正蓝 `#1E1EFF`（240°，饱和度 100%）、黑键品蓝 `#4169E1`（225°，饱和度 73%）——
  同色系靠**饱和度 + 明度**分开，黑键比白键更柔一点，不离群。
- 预告行沿用「第一排纯、第二排柔」的层次：饱和度全部降下来（右手 85% → 46%），
  两排不会混。

### 19.3 预设配色版本号（老用户自动升级）

预设颜色是**代码里写死**的，改版后老用户 localStorage 里存的还是旧版方案色
（浅粉），会出现「代码改了但屏幕上没变」。于是加了一个版本号：

```
src/led/schemes.ts → export const SCHEME_COLOR_VERSION = 2
src/store.ts       → PersistedPrefs.ledSchemeVersion
```

启动时比对：

| localStorage 里的方案 | 处理 |
|---|---|
| `c` / `d`（预设） | 版本对不上 → **自动换成新版预设色**，并写回新版本号 |
| `custom`（手动调过） | 一律不动 |
| `auto` | 运行时按曲速挑 C / D，不读存的颜色 |

`applyLedSchemeColors()` / `resetLedColors()` 写入颜色时一并记下当前版本号，
下次预设再改版还能继续自动升级。

## 21. 校准模式改成「调色预览」（2026-11-02）

### 21.1 反馈

§20 的校准模式做错了：用户要的是**调色**用的 —— 亮起几个位置**显示自己的颜色**，

### 21.2 现在的行为

### 22.3 方案 C 定稿色

`src/led/schemes.ts`：

```
当前音(主灯带): 左白 #1E1EFF · 左黑 #4169E1 · 右白 #FF0000 · 右黑 #C8102E
预告行(上灯带): 左白 #006AFF · 左黑 #11FF00 · 右白 #FF0000 · 右黑 #FF0033
```

层次不再靠「降饱和」，改成**亮度**：上灯带 = 主灯带 × 上灯带比例 × 阶梯（§19）。
方案 D 保持原样（浅品红 / 冰青），给快板和复杂灯光环境用。

### 22.4 配色版本迁移

`SCHEME_COLOR_VERSION` **2 → 3**。

用户 localStorage 里存的是旧版方案 C 的色，直接读会看到「老配色」；
store 启动时拿这个号对比 —— 用了预设方案（c/d）的话**自动升级**到新版配色；
自己手动调过的（`custom`）**不动**。

### 22.5 一处歧义（按标签实现）

原话「C 方案的上下两条灯带都用预告行的颜色」有两种读法：

| 读法 | 结果 |
|---|---|
| **A（采用）** 按**标签**对号入座 | 主灯带 = 「当前音」那组，上灯带 = 「预告行」那组 —— 用户给的 8 个色全部用上 |
| B 字面读 | 两条带都用「预告行」那组（`#006aff`/`#11ff00`/`#ff0000`/`#ff0033`）—— 「当前音」那组就没用了 |

采用 A，理由：用户一次给了 **8** 个色、还标了「当前音 / 预告行」两个标题 —— 只用 4 个的话不用给两组；
而且「当前音」那组跟用户前一轮定的「右手红/深红、左手正蓝/品蓝」完全对得上。

要改成 B 的话，改 `src/led/schemes.ts` 里 `SCHEME_C.current` 的 4 个值即可（跟 `upcoming` 一致）。
